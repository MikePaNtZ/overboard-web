One board. Two machines.

A Floatwheel-class DIY onewheel with a Raspberry Pi bolted on — and a control stack written from scratch in Rust.

Driverless

The one that teaches

Tethered, wheel off the ground, nobody aboard. The Pi owns the whole cascade and the balance controller is written from first principles. This is the real project.

Ridden

The one that's fun

Balance stays on proven VESC/Refloat firmware as sole authority. The Rust stack observes and advises — and has zero ability to command motion.

Open

The one you can copy

Off-the-shelf parts, no custom PCB, pinned toolchain. Design docs, the sim model, and the logs from runs that went badly — all public.

One control loop. Two backends.

A single BoardIo trait is the seam. Swap the implementation and the same controller drives either a physics engine or a motor — which is what makes sim-first honest rather than aspirational.

01 · input Setpoint Velocity and turn rate from a gamepad. Built to grow into GPS waypoints.
02 · the work Rust control core Pure and deterministic — no clock reads, no I/O. Estimator, cascade, safety envelope.
03 · the seam BoardIo One synchronous call in, one observation out. The backend owns the clock.
04 · world MuJoCo or VESC A deterministic sim with injected worst-case noise — or a real hub motor over CAN.

Real-time, measured

SCHED_FIFO, mlockall, isolated cores. The gate is p99.9 wake jitter under 100 µs with zero missed deadlines across an hour.

No ideal-only CI

Every change replays the balance regression against a versioned worst-case profile of latency, noise and quantization.

One log schema

Sim and steel write the same versioned MCAP, with the resolved parameter set in the header. Replayable in Foxglove.

Phase 0

Sim-first, mostly no hardware Now

MuJoCo model, the BoardIo seam, and a full Rust balance controller in raw-current sim. In parallel: measuring the latency number that decides the architecture.

Phase 1

Bench driverless

Pi, SPI IMU and CAN into a real board. Tethered, wheel off the ground, nobody near it. Correlate sim against bench.

Phase 2

Ridden mode, same hardware

Refloat balances; the Rust stack observes and advises. Gated behind a safety architecture and an adversarial review that has to pass first.

Phase 3

The ambitious stuff

GPS waypoints, a roll-axis mass shifter so a riderless board can turn, commanding from a phone. All sim-first, all speculative.

On safety: motion authority is decided by flashed firmware, not a runtime flag — the ridden binary contains no motion-command code at all, and a hardware kill sits in series with motor power in both modes. Nothing here is a product, and none of it is certified.
